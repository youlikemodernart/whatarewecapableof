PRODUCT SHAPE

01

PiOp

The product: a supported way to carry dependable Pi behavior from one installation to another.

02

Minimal

The delivery model: ordinary Pi packages, portable files, a Recipient Profile, and a small bootstrap.

03

Foundation + Modules

The installed shape: a dependable baseline, then selected additions with their own requirements and boundaries.

Foundation

DEPENDABLE BASELINE

The Foundation is designed for ordinary terminal use. It does not depend on a particular model provider, browser, terminal application, device, or account.

Modules add specialized tools and working environments. Each one is selected deliberately, checked against its dependencies, and verified separately.

GitHub Ops

Accepted source

Ready requires: authenticated account, target permissions, and operation-specific approval

Surf

Accepted source

Browser control for testing, screenshots, form work, page inspection, and logged-in browser sessions.

Ready requires: Node 22 runtime proof and an approved browser pairing

Figma production

Accepted source

Native editable Figma production, inspection, comparison, verification, and recovery.

Ready requires: provider, plugin, target, write, readback, and recovery proof

Figma Write Bridge

Accepted source

A separate bridge for controlled Figma writes, with deterministic unavailable-provider behavior.

Ready requires: bridge, plugin, listener, target, and write proof

Availability describes reviewed product status, not installation or readiness on a recipient's machine.

Add working methods

5 PACKAGES / 7 SKILLS

Skills add focused methods for particular kinds of work. They can travel with the installation without becoming part of the universal baseline.

This library shows each released package's purpose, scope, risk tier, exact version, methods, and declared boundaries. Read what a package can access or change before including it.

Assemble the packages you want, then generate a fulfillment request. We review the combination before preparing a recipient-specific ZIP. Nothing is installed from this page.

Risk tiers run from T0 (text-only skills and prompts) to T3 (can touch accounts, credentials, live services, or files). Scope is either global (applies across Pi) or project-local (stays in one workspace). The package-data row describes what ships in the release; runtime handling of user-provided content follows the selected method and active request.

From selection to installation

PRIVATE FULFILLMENT

Private GitHub is the source authority. It holds source history, exact versions, tests, and reproducible release evidence. Recipient delivery remains separate.

  • Choose a skill set and send the generated request.
  • We review package compatibility, scope, and risk before fulfillment.
  • If approved, we prepare a recipient-specific ZIP and share only that file through private Google Drive.
  • The delivery email includes the exact copy-and-paste Pi setup prompt.

A GitHub account is not required for recipient delivery. Payment does not change fulfillment priority, package access, or repository permissions.
