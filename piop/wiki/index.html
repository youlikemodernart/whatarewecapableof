PiOp Minimal is a portable, curated setup for Pi, the agent runtime.[1] It gives a recipient a dependable way to use Pi for real work across files, terminal, public web, models, skills, and delegation while keeping authority, privacy, and recovery explicit. "Minimal" describes the delivery model: ordinary Pi packages, portable files, a Recipient Profile, and a small bootstrap, rather than a custom installer.[2]

PiOp tracks which capabilities are present, what it must ask before acting, where work belongs, and how to leave a recovery path. An installation adds only what a reviewed plan approves; the product explains what an installation can include and prepares a reviewed request.

Overview [edit]

A capable Pi setup accumulates useful operating behavior across instructions, skills, extensions, helper tools, profiles, model access, and recovery knowledge. Without a product layer, that setup is hard to transfer and support. PiOp turns the accepted parts into one understandable, recipient-ready product with one source of truth.[2]

PiOp distinguishes several capability states. Known, installed, configured, authenticated, available, verified, and ready describe different conditions: a supported tool can be known without being installed, and installed without being ready.

Foundation [edit]

The Foundation is designed for ordinary terminal use. It does not depend on a particular model provider, browser, terminal application, device, or account.[2]

Skills [edit]

Skills add focused methods for particular kinds of work. They travel with an installation without becoming part of the universal baseline. Risk tiers run from T0 (text-only) to T3 (can touch accounts, credentials, or live services); scope is global or project-local. A recipient assembles a set, and a reviewed request is generated from it. Selection installs nothing on its own.

Delivery [edit]

Private GitHub is the source authority: it holds source history, exact versions, tests, and reproducible release evidence.[2] Recipient delivery is separate.

  • A recipient chooses a skill set, and the generated request is sent.
  • Package compatibility, scope, and risk are reviewed before fulfillment.
  • On approval, a recipient-specific ZIP is shared through private Google Drive.
  • The delivery email carries the exact copy-and-paste Pi setup prompt.

Boundary: A GitHub account is not required for delivery. Sends, deployments, credentials, and account changes keep their own approval boundaries.
